# Las once librerias de las que dependen las cifras del trabajo van FIJADAS con == y no con >=.
# La pila de servicio (fastapi, uvicorn, pydantic, httpx) va sin version aqui y queda fijada en
# requirements-lock.txt, que es el fichero que reconstruye el entorno identico. Varios resultados
# (el recorte a cero de las predicciones, el tratamiento nativo de NaN de XGBoost y la activacion
# de la capa de salida de Keras) dependen del comportamiento concreto de una version de libreria:
# con estas versiones exactas el proyecto reproduce sus cifras digito a digito; con otras, no esta
# garantizado.
#
# Son las versiones con las que se generaron todos los artefactos de data/processed/, models/ y
# reports/, y los propios artefactos las llevan grabadas en sus metadatos.
#
# Entorno del proyecto: conda `tfm`, Python 3.11.15. Se crea desde cero con:
#
#     conda create -n tfm python=3.11 -y
#     conda activate tfm
#     pip install -r requirements.txt
#
# `requirements-lock.txt` (163 paquetes, incluidas las transitivas) es el `pip freeze` de ese
# entorno y permite reconstruirlo identico, no solo equivalente.
#
# Para arrancar la API, usar `python -m uvicorn` y no `uvicorn` a secas: el ejecutable suelto usa
# el primer Python del PATH y puede fallar con un ModuleNotFoundError.
